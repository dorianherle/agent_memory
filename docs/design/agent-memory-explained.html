The system in one page

Agent Memory

Fresh agents. Persistent goals. Better next attempts.

Every new question starts with a fresh context. The agent receives the active goal, relevant knowledge, and the next unfinished step.

What persists

Goal state: the objective, constraints, progress, and next action.
Knowledge: verified facts and their sources.
Procedures: methods, when they apply, and how to check them.
Evidence: attempts, results, and the code that was tested.

How it gets better

Try → verify → save the lesson → improve the next choice.

Requirements rule out invalid outcomes. Failed attempts discourage repeating the same mistake. Successful procedures become preferred starting points when their conditions match. Changed conditions trigger a recheck.

Example: an export exceeds its memory limit because a helper buffers the whole file. The next agent starts by fixing that helper, using the saved diagnosis and tests.

How goals stay separate

Each goal has its own Git repository and workspace. Switching subjects selects another goal. Only selected, applicable lessons cross between them.

What makes this work

A runner starts fresh contexts, supplies the brief, saves progress, and requires the goal's checks before recording success. The model stays the same; its starting information and choices improve through evidence.

Proposed design. Lessons guide the search; they do not guarantee success.
