Independent evidence audit. Date: 2026-10-13.

The records support small, local test results. They do not establish reliable compaction, general method superiority, or fundamental discovery.
This review made no model calls and ran no training. It did not inspect E3 model or dependency files.
The reviewer created only this audit file.

1. Record checks.
All E1-E8 protocol, script, result, and report files were present at the final file check.
All 57 successful experiment calls have native usage records. Their totals match the saved completion events.
Those events contain agent messages only. No tool-use events were found.
Saved prompts match the recorded input construction. Protocol and source hashes match where the tests record them.
The categorical grades checked in E1, E2, E5, E6, and E8 match their saved results.
E7 answer and source grades also match. E4 score totals match the recorded question grades.
I also counted 34 packets and retrieval contexts with the declared o200k_base tokenizer. All counts match.
These checks establish record consistency. The authors still construct both the tests and the expected answers.

2. Input isolation.
Hidden answer dictionaries do not enter the saved test prompts.
Compactor prompts do not contain the later evaluation questions in E1, E2, E4, E5, or E6.
E6 hidden questions do not enter its writers or public preservation reader.
E4 and E7 use one shared answer cue: an unknown lateral rate requires the exact answer "No; unknown".
That cue applies to all arms. This item is not a wholly blind answer test.
The CLI calls use separate temporary directories and disable memory and tools.
Native input usage still includes a large CLI context. The model receives more tokens than the saved task prompt alone.

3. E1: recursive drift.
The inconclusive conclusion follows the frozen rule. Several packets exceed the 260-token cap.
Prose passes 9 of 9 question groups. The ledger passes 8 of 9. The full-history control passes all groups.
The ledger omits the prohibition on replacing an unknown quantity with zero.
This loss occurs when H3 first introduces the rule. It is an extraction loss, not loss after successful retention.
The observed results do not show a ledger benefit. One history cannot establish a failure rate.

4. E2: rule abstraction.
All receivers pass the frozen labels. No prediction advantage for the rule prompt is measured.
For release, the rule packet has 145 tokens. The summary has 232 and exceeds the 220-token limit.
For independent trials, the rule packet has 156 tokens. The summary has 108. Both pass.
The release result supports a local packet-size benefit. It does not establish total token savings.
The source uses a familiar build-validity relationship. The model can apply prior knowledge to that relationship.
The rule packet places a general relationship under "Observations". Correct labels do not establish correct statement-level source classification.
This test has one handoff. It does not test progressive compaction or new scientific laws.

5. E3: weight memory.
The inconclusive conclusion is correct. Complete pretrained weights were unavailable when the setup cap was reached.
No weights were loaded. No training or answer generation ran. Parameter and adapter counts are unavailable.
The reported 0.14-second script time excludes the recorded 180-second setup attempt.
Dependency setup time is not measured in that script total.
This is a setup failure. It provides no evidence for or against useful parametric memory.
The planned lexical grader would not establish faithful meaning or source retention, even if training had run.

6. E4: query memory.
The original global packet has 284 tokens and violates the 180-token target.
The separate repair protocol preserves the original result. Its new global packet has 164 tokens and meets the target.
Each reader sees all 12 question contexts in one batch. It can use evidence assigned to other questions.
Retrieval supplies 2,091 memory tokens across that batch. It exposes 37 distinct records with a 636-token combined text.
The repaired global arm repeats one 164-token packet. Its total is 1,968 memory tokens.
Thus, E4 does not test isolated readers with equal total context.
Some exact-score failures are correct equivalents: "11 min", "37 times", and "135 degrees C" expressed as "135 °C".
The repaired global answer score of 9 of 12 is an exact-format score. It includes two correct equivalents.
Its cooling-hold answer is a clear factual error. It gives the 93-second etch duration instead.
Exact source scoring also distinguishes a source range from the correct individual record ID.
The source-presence flag uses substring matching. It can count S24 in the range S01-S24 without a specific statement-to-source link.
E4 supports a local retrieval observation. It does not establish a fair general performance comparison.

7. E5: task state.
All packets meet the 180-token target. Both full-history controls pass.
The checkpoint ties the knowledge summary on export and has fewer scored errors on backfill.
The backfill knowledge receiver requests missing state. It does not falsely claim completion.
The checkpoint packets are longer. Both arms share a writer call.
The histories state the required first action. This test measures preservation of that task state.
The backfill checkpoint omits the explicit publication prohibition. This constraint is outside the frozen score.
Passing every scored field therefore does not establish complete constraint preservation or correct task execution.

8. E6: checked compaction.
The inconclusive conclusion follows the frozen rule. The initial packet has 174 tokens against a 160-token cap.
The repair has 161 tokens and is rejected. No checked packet is accepted.
The public check passes all 6 groups. Only the size failure is sent to the repair writer.
Both hidden packet readers and the full-history control pass all 10 groups. The measured accuracy change is zero.
The rejected repair's hidden score is diagnostic only.
Public questions and source maps cover predefined facts. They do not constitute an audit of all possible source claims.
This run does not establish a reliable preservation-and-repair method.

9. E7: isolated retrieval diagnostic.
Each of its 12 calls receives one query and one assigned memory. This removes E4's shared-context problem.
The global arm answers 3 of 4 questions correctly. Retrieval and full history answer all 4 correctly.
Exact source scores are 2 of 4, 4 of 4, and 4 of 4, respectively.
The global reader correctly returns UNKNOWN for a cooling hold absent from its packet. This is a safe response.
Retrieval gets the cooling hold from the retained archive.
The common maximum is 180 tokens. Actual global packets have 164 tokens. Retrieval packets have 175 to 180.
The test selects four known E4 questions after E4 results are available. It reuses the adaptive global packet.
This is useful local evidence for retrieval. It is not independent confirmation, an exact-size comparison, or a reliability estimate.
Its reported native input differences cannot be attributed only to memory size. CLI input overhead differs between call groups.

10. E8: no-memory diagnostic.
Only the E2 MEMORY field changes. The receiver instruction and questions remain exact.
Both readers return unknown for every question.
Release scores are 0 of 3 observed and 0 of 8 unseen. Independent scores are 0 of 3 observed and 4 of 4 unseen.
The stated no-memory hypothesis correctly fails.
The result shows that supplied memory changes answers under this instruction. Correct unseen unknowns alone do not show case knowledge.
The instruction requires unknown when memory does not support an answer. This control does not isolate prior knowledge after memory is supplied.
E8 is adaptive and has one call per dataset. It does not prove purely source-derived learning.

11. Cost and retained evidence.
The 57 experiment calls use 698,515 native input tokens and 10,089 native output tokens.
The successful preflight adds 13,080 input tokens and 15 output tokens.
Known totals with that preflight are 711,595 input tokens and 10,104 output tokens.
The failed first preflight has no native usage. Its usage is unknown, not zero.
These totals exclude parent and subagent work, dependency setup, and weight-download resources.
The successful runs stay within their recorded call and wall-time limits. Packet-limit failures remain visible.
No suite-wide native token ceiling is recorded. Packet limits cannot establish compliance with an unstated total-token budget.
Original histories, prompts, answers, and failed setup records remain in the lab. The E4 archive matches its protocol.
Retained source files do not prove that a compact packet preserves every constraint or that a later agent can retrieve them.
Early inventory snapshots were incomplete because calls were still running. They have been replaced.
The final inventory includes all eight experiments and the 57 successful experiment calls.

12. Summary review.
The generated summary states the main limits and preserves the negative results.
It correctly separates proposals from tested methods. It does not claim a breakthrough or a generally reliable system.
Three wording changes were sent to the parent reviewer.

The summary initially reverses this to a memory-requirement hypothesis. Its reported scores and bounded finding remain correct.

The strongest supported claims are local packet transfer and query-based recovery of recorded facts.
The suite does not demonstrate reliable recursive compaction, successful weight memory, autonomous task completion, or fundamental discovery.
